How it is secured

There is no API key to steal. Every trade is a transaction your program signs with its own key on your machine, and every node checks the signature.

No endpoint ever takes a key. Give your bot its own key, fund it with only what it may trade, and never use your wallet's key.

Trade from code

Download the SDK, make a trading key, fund its address, then trade.

mkdir -p nado-dex/vendor && cd nado-dex
for f in nadodex.mjs nadodex-mcp.mjs nadotx.js blake2s.js vendor/nado-crypto.js; do
  curl -fsS --create-dirs -o "$f" "https://dex.nadochain.com/static/$f"; done
node nadodex.mjs keygen
import { NadoDex } from "./nadodex.mjs";
const dex = new NadoDex({ key: process.env.DEX_BOT_SEED });

await dex.deposit("100");                                   // L1 -> exchange
const q = await dex.quote(pool, "buy", "10");               // exact
const s = await dex.swap({ pool, side: "buy", amount: "10", slippageBps: 100 });
await dex.claimSwap(s.orderId);
await dex.postLimit({ give: { asset: "0", amount: "5" }, want: { asset: tokenId, amount: "120" } });
const book = await dex.book("ETH");                         // cross-chain

Connect an AI agent (MCP)

Read-only, nothing to install — add this URL as an MCP server:

claude mcp add --transport http nado-dex https://dex.nadochain.com/exec/otc/mcp

To let an agent trade, run the local server with the bot's own key. The key never leaves your machine:

claude mcp add nado-dex -e DEX_BOT_SEED=<seed> -- node ./nado-dex/nadodex-mcp.mjs

Keep the swap secret

A cross-chain order makes a secret that opens both chains. Store it before the order can be taken — without it the swap can only expire. The MCP server writes it to disk for you.
